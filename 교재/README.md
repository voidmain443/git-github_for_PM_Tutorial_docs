# 교재 폴더 — PM 트랙 Day1~4 (완료) · Product 트랙 Day5~8 (완료) — 8일 40종 전부

프로젝트 매니지먼트 4일 특강의 PM 트랙 자료 일체. **PM 트랙 4일(Day1~Day4) 완료** — 교재·워크북·그림·템플릿 4일치가 모두 빌드된다. 교재·워크북·사례 원고는 마크다운(`.md`)이 정본이고,
그림·템플릿은 LaTeX/matplotlib 소스에서, 책(PDF)은 pandoc으로 빌드한다.
**슬라이드만 예외 — 소스는 `PM트랙/DayN_슬라이드_body.tex`(Beamer)이고 `DayN_슬라이드.md`는 거기서 생성되는 텍스트 미러다.**
**원고를 고친 뒤 `./build.sh` 한 번이면 전부 다시 만들어진다.** 날(Day)마다 파일 이름 규칙이 같아서
`build.sh`는 날을 인수로 받는다(아래 "재빌드").

## 재빌드

`build.sh`는 Day1~4를 PM 트랙(`PM트랙/`, `PM_DayN`), Day5~8을 Product 트랙(`Product트랙/`, `Product_DayN`)으로 자동 분기한다. `./build.sh books Day5`는 Product 공통 문서 6종(사례 정본·학습안내·책받침·색인·계획·제작노트)도 함께 만든다. ㉛~㊵ 글리프는 Apple SD Gothic Neo에 없어 `build/header.tex`·`PM트랙/src/preamble.tex`·템플릿 `wbstyle.sty`가 Hiragino Sans W3로 대체한다(pandoc 책은 xeCJK 문자 클래스도 Default로 돌려야 적용된다).

```bash
cd 교재
./build.sh                    # 전부(그림 → 템플릿 → 슬라이드 → 책), 모든 날 (약 5분)
./build.sh books              # 책만, 모든 날 (Day1~Day4 교재·워크북, 공통 사례 연구)
./build.sh books Day3         # Day3 교재·워크북 PDF 만 (가장 자주 쓰게 될 형태, 약 1분)
./build.sh figs Day1          # Day1 그림만   (그림/PM_Day1/src/*.tex, *.py)
./build.sh templates Day2     # Day2 템플릿만 (템플릿/PM_Day2/src/build.sh 에 위임 → PDF 10 + 통합본 2)
./build.sh slides Day2        # Day2 Beamer 슬라이드만 (body.tex → 슬라이드판·노트판 PDF + md 미러 재생성, 약 30초)
./build.sh all "Day1 Day2 Day3 Day4"   # 여러 날은 따옴표로 묶어 전달
```

- 첫 인수 = 단계(`all`·`figs`·`templates`·`slides`·`books`), 둘째 인수 = 날(`all`·`Day1`·`Day2`·…). 둘 다 생략하면 `all all`.
- 날 목록은 자동 탐지된다: `그림/PM_DayN`, `템플릿/PM_DayN`, `PM트랙/DayN_교재.md` 등이 있으면 그 날이 대상이다.
  소스가 없는 단계는 `(건너뜀)` 으로 표시하고 지나간다.
- 공통 사례 연구(`공통/가상회사_온담F앤B.md`)는 날이 `all` 또는 `Day1` 일 때 함께 만든다.
- 그림·템플릿은 각 `src/build.sh` 가 있으면 그것을 호출한다(그림은 이름 목록을 넘겨 호출, 템플릿은 인수 없이 전체).
  그림 한 장만 다시 만들 때는 `그림/PM_Day2/src/build.sh fig_3_2_cpm_g2_g3` 처럼 이름만 넘긴다.
- 책 빌드가 실패하면 `FAIL` 과 함께 `build/log_<책이름>.txt` 전체를 출력하고 멈춘다(예전 PDF 를 "ok" 로 잘못 보고하지 않는다).

### 책 빌드가 하는 일 (build/book.lua · build/header.tex)

md 원고는 그대로 두고 PDF 출력만 손질한다.

- 첫 `#` 제목을 표지 제목으로 쓰고(" — " 앞뒤를 제목/부제로 분리), 원고의 수동 `## 목차` 절은 빼고 쪽번호 있는 목차를 생성
- 목차 앞의 머리말(문서 소개 인용문)은 표지 다음 쪽에 배치
- 그림 아래 이탤릭 설명문(`*그림 1-1. …*`)을 그림 캡션으로 합쳐 중복 제거. LaTeX 자동 라벨("그림 1:")은 숨김 — 원고 번호를 쓴다
- `.png` 그림은 같은 이름의 `.pdf` 가 있으면 벡터로 교체
- 표: 셀 내용 폭을 재서 열 너비를 비례 배분, 6열 이상 `\small`, 8열 이상 `\footnotesize`, **10열 이상은 가로(landscape) 쪽**.
  가로표(RTM·CPM·리스크 등록부·이해관계자 등록부 등)는 열 너비를 다시 잰다 — ID·날짜·숫자처럼 짧은 열은 제 폭을 그대로 주어
  낱말 중간 줄바꿈이 없게 하고, 남는 폭은 글자 총량이 많은 문장 열에 나눠 준다
- 코드 블록(워크북 빈 템플릿 원문): 긴 줄 자동 줄바꿈, 한글은 본문 폰트로 출력(xeCJK).
  단, 선 문자(─│┌└▶◀)로 그린 관계도 블록은 줄바꿈하면 그림이 깨지므로 줄바꿈 없이 들어가는 글자 크기를 고르고, 그래도 안 들어가면 가로 쪽에 놓는다
- 본문 폰트에 없는 글자 치환: 📄 → ▶, 수학 마이너스(−) → –, ✔ → ✓, 코드 안 ※ → *
- `--number-sections` 는 쓰지 않는다 (원고에 "제1장", "1.2" 번호가 이미 있음)

워크북·사례 연구는 `## N.` 이 최상위이므로 `--shift-heading-level-by=-1` 로 장(chapter)으로 올린다.
교재는 `# 제N장` 이 장이다(Day2 교재의 `# 서문` 도 장으로 취급된다).

## 필요한 도구 (macOS)

```bash
brew install tectonic pandoc poppler        # tectonic 0.17 / pandoc 3.11 / pdftoppm·pdfunite·pdfinfo
```

## 확인 방법

```bash
pdfinfo PM트랙/Day3_교재.pdf | grep Pages                 # 쪽수
pdftoppm -png -r 70 -f 12 -l 12 -singlefile PM트랙/Day3_교재.pdf p12   # 특정 쪽을 PNG 로
pdftoppm -png -r 40 PM트랙/Day3_워크북.pdf sheet          # 전 쪽을 40dpi PNG 로 뽑아 훑어보기
pdfinfo -f 1 -l 99 PM트랙/Day3_워크북.pdf | grep "rot:" | awk '$NF!=0'   # 가로(landscape) 쪽 목록
```

빌드 로그의 `Overfull \hbox` 경고는 표·코드에서 몇 pt 넘친다는 뜻으로 대부분 무해하다(전체 로그는 `build/log_*.txt`).
글자가 잘리거나 겹치면 해당 쪽을 PNG 로 뽑아 확인하고, 표라면 `build/book.lua` 의 `Table` 함수
임계값(열 수·`TEXT_EM`·가로표 폭 계산)을, 그림이라면 `header.tex` 의 `\pandocbounded`(최대 높이 0.62\textheight)를 조정한다.
`could not represent character` 경고가 나오면 그 글자를 `book.lua` 의 `fix_chars` 치환표에 추가한다.
