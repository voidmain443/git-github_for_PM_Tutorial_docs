# 07. 계획 통합과 실행

이제 스폰서는 하나로 연결된 계획을 보고 싶어 합니다. 통합 승인 후에는 회의 결정을 작업으로 바꾸고 실행 증거를 관리해야 합니다.

통합 관리는 각 분야의 계획과 결정을 서로 맞추는 업무입니다. 문서가 각각 그럴듯해도 외주 납품일이 시험 시작일보다 늦거나 필요한 인원이 없으면 하나의 실행 가능한 계획이 아닙니다. 기준선 승인은 비교할 원래 계획을 고정하는 결정입니다. 이후 PM은 작업을 지시하고 결과 증거를 확인합니다. 지시한 사실, 수행한 사실, 검증된 사실은 서로 다른 상태입니다.

이 단원은 설명 → 자료 조회 → 예제 → 직접 확인 → 검토·수정 → 다음 업무 순서로 진행합니다. 웹 입력은 필요하지 않습니다. 문서를 작성할 때는 양식을 내려받고 같은 문서의 버전을 이어 갑니다.

## 1. 분야별 계획을 하나의 실행 가능한 계획으로 맞추기

자료 단계: S1. 관련 프로세스: 4.2.

[S02 조직·권한·문서 규정](../02_원천문서/S0/S02.md) · [S06 기술 추정과 활동·자원 자료](../02_원천문서/S1/S06.md) · [S07 품질·리스크 워크숍 원문](../02_원천문서/S1/S07.md) · [S08 조달 요청·제안서·팀 협업 합의](../02_원천문서/S1/S08.md)

### 이번 업무를 이해하기

통합계획은 문서 목록만 모은 것이 아닙니다. 같은 요구가 범위·일정·비용·시험에서 다른 뜻이 되지 않는지 비교해야 합니다. 각 문서의 버전과 담당자를 정한 뒤 연결 한 건씩 따라갑니다.

### 가져올 문서와 현재 상태

D01,D08~D31의 계획 부분

### 자료를 찾아 읽기

1. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S02 → 조회 → 목록의 S02 상세를 엽니다. 읽을 부분: 역할별 권한, 문서 검토·승인 및 변경 상정 절차. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

2. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S06 → 조회 → 목록의 S06 상세를 엽니다. 읽을 부분: A~G 기간·선행, WBS, 인력·단가, 월별 비용 배분. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

3. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S07 → 조회 → 목록의 S07 상세를 엽니다. 읽을 부분: 품질 기준, K01/K02 확률·영향·평가 규칙. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

4. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S08 → 조회 → 목록의 S08 상세를 엽니다. 읽을 부분: 업체 제안 점수·가중치, 회의·보고 주기와 참여 상태. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

찾지 못하면 현재 자료 단계와 이전 검색조건을 확인하세요. 파일로 읽을 때는 같은 ID의 원천 문서를 사용합니다. SQL은 선택 경로입니다.

### 함께 따라 하는 예제

대사·예외 패키지의 계약 납기는 S19의 12월 11일입니다. D14의 통합검증 E 착수가 그 납품 후인지 확인합니다. “계약 검토 완료” 대신 실제 비교한 날짜와 문서 버전을 D02에 남기면 통합 검토 증거가 됩니다.

### 문서에 반영하기

D02 통합관리계획 양식을 사용합니다.

1. D02에 분야별 문서 버전과 소유자를 등록합니다.

2. 요구→WBS→활동→비용→시험과 자원·계약을 대조해 불일치를 수정합니다.

3. 수정한 분야 계획을 통합 상정하고 승인 대기로 둡니다. 다음 단계의 S1A에서 승인 조건을 대조합니다.

### 직접 확인해 보기

개발 C의 인원·공수와 일정, 위험 대응과 예비비의 포함 여부를 비교하세요. 분야 검토가 끝나도 지금 S1에서는 통합 승인 대기입니다.

### 검토 의견으로 수정하기

초안 “문서가 모두 있으므로 승인 가능” → 상호 모순을 확인하지 않았습니다 → 요구→WBS→활동→비용→시험과 자원·계약 조건을 대조한 결과를 추가합니다.

검토 역할: 윤서진. 문서 목록만 있고 상호 모순 점검이 없나요? 계약 납기와 E 착수, 자원과 공수, 예비비와 위험을 실제로 대조하세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

### 다음 업무로 넘기기

D02 통합관리계획의 현재 버전과 근거를 보존합니다. 이 문서를 다시 사용할 때 현재 상태가 초안·분야 검토·승인 중 무엇인지 확인합니다. 문서 본문은 한 번 작성하고 수행표에는 위치만 남깁니다.

### 다음에 이어 할 일

계획 승인과 계약을 확인하고 킥오프 준비하기 단계로 이어집니다. 현재 작성한 문서의 항목·근거를 가져가세요. 자료 단계가 바뀌면 먼저 현재 기록을 보존합니다.

## 2. 계획 승인과 계약을 확인하고 킥오프 준비하기

### 이번 단계의 순서

S1에서 통합 대조와 수정을 마친 뒤 S1A를 엽니다. AP01 조건과 분야 계획을 대조해 승인 버전을 보관합니다. CT01/PO01은 선정 권고와 다른 사건입니다. 기준선과 계약이 확인된 뒤 다음 단계에서 회의 결정을 작업지시로 바꿉니다. 예산·기준선 메뉴의 BL01 상세에서 승인과 월별 배분을 함께 확인하세요.

### 자료를 찾아 읽기

1. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S09 → 조회 → 목록의 S09 상세를 엽니다. 읽을 부분: AP01, 계약·발주와 킥오프 작업지시의 구분. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

### ERP 목록과 문서 연결하기

ERP에서 「예산·기준선」 → 「초기화」 → 정확히 일치 항목 「버전」 → 값 「BL01」 → 「조회」 순서로 진행합니다.

BL01을 눌러 승인·월별비용계획을 엽니다. AP01과 금액·시점을 D02/D17 초안에 대조한 뒤 승인 버전을 보존합니다. PO01 발주가 실제 비용이나 지급을 뜻하지 않는 점도 구분합니다.

조회 결과가 다르면 현재 자료 단계와 남은 검색조건을 먼저 확인하세요. 원천 ERP는 읽기 전용이며 작성은 내려받은 문서에서 합니다.

## 3. 킥오프 결정을 담당자에게 실행 가능한 지시로 넘기기

자료 단계: S1A. 관련 프로세스: 4.3.

[S09 기준선 승인과 계약·킥오프](../02_원천문서/S1A/S09.md) · [S02 조직·권한·문서 규정](../02_원천문서/S0/S02.md)

### 자료를 찾아 읽기

2. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S02 → 조회 → 목록의 S02 상세를 엽니다. 읽을 부분: 역할별 권한, 문서 검토·승인 및 변경 상정 절차. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

찾지 못하면 현재 자료 단계와 이전 검색조건을 확인하세요. 파일로 읽을 때는 같은 ID의 원천 문서를 사용합니다. SQL은 선택 경로입니다.

### 함께 따라 하는 예제

S09의 표본검증 결정은 WO01-A로, 담당 이현우·기한 10월 23일·표본검증 증거로 옮길 수 있습니다. D03에 지시 상태로 등록합니다. 아직 11월 실행 자료가 없으므로 완료라고 쓰지 않습니다.

### 문서에 반영하기

1. S09의 회의 결정을 D03 작업ID·담당·기한·완료 증거로 바꾼다.

2. 승인된 범위와 연결하고 지시일과 실제 완료일을 따로 둔다.

3. S20 공개 후 증거를 붙여 상태를 갱신하고 이슈는 별도 행으로 관리한다.

### 직접 확인해 보기

환경점검 결정을 같은 형식으로 작성하세요. 작업과 이슈를 다른 행으로 관리하고 S2의 S20을 받은 뒤 완료일과 확인자를 대조합니다.

### 검토 의견으로 수정하기

초안 “킥오프 당일 환경점검 완료” → 지시와 실제를 혼동했습니다 → 지시 기록을 보존하고 실행 증거 수신 시 상태를 갱신합니다.

검토 역할: 이현우. 작업지시를 작성한 날짜에 모두 완료 처리했나요? 수행 증거가 공개되기 전에는 지시·진행 상태로 두세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

1. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S10 → 조회 → 목록의 S10 상세를 엽니다. 읽을 부분: 11월 30일 PV/EV/AC, 시험·자원·참여·잔여 위험의 상태. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

2. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S11 → 조회 → 목록의 S11 상세를 엽니다. 읽을 부분: CSV 요청의 이유, 세 대안의 비용·일정·자원 영향. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

찾지 못하면 현재 자료 단계와 이전 검색조건을 확인하세요. 파일로 읽을 때는 같은 ID의 원천 문서를 사용합니다. SQL은 선택 경로입니다.

### 함께 따라 하는 예제

S11의 CSV 요청은 운영 필요를 기록한 뒤 변경 검토로 넘깁니다. D31에는 누가 무엇을 요청했고 어떤 설명과 다음 협의를 할지 적습니다. 아직 승인되지 않은 제공일을 확약하지 않습니다.

### 문서에 반영하기

D31 참여계획·평가 양식을 사용합니다.

1. S10/S11의 운영 요청과 가맹점 관심을 D31에 기록한다.

2. 요청에 대한 답변·영향 검토·다음 협의 행동을 정한다.

3. CSV는 CR로 접수하고 아직 제공 날짜를 확약하지 않는다.

### 직접 확인해 보기

운영과 가맹점의 관심을 구분해 설명할 내용을 정하세요. 요청·답변·결정이 어디에 기록되는지 D31과 D06을 연결합니다.

### 검토 의견으로 수정하기

초안 “만족도를 위해 요청 기능을 즉시 약속” → 승인 전 범위가 늘어납니다 → 필요를 확인하고 영향 분석·결정 시점을 안내합니다.

검토 역할: 박다은. 이해관계자 만족을 위해 미승인 기능을 약속했나요? 요구 수용 검토와 구현 승인을 나누세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.
