# 09. 검수·이관·종료

완성된 제품, 검수 증거, 지급 내역이 도착했습니다. 프로젝트를 끝내도 운영과 보증·편익 책임은 남습니다. 누가 이어받을지 명확하게 정리하세요.

검증은 결과가 정해진 품질 조건을 충족하는지 확인하는 활동이고, 인수는 현업이 이를 받아들이는 결정입니다. 운영이관에는 시스템뿐 아니라 담당자·매뉴얼·복구·지원 창구도 포함합니다. 프로젝트 종료는 인수·계약·재무·자료·자원을 정리하고 잔여 책임을 인계하는 일입니다. 편익은 도입 이후 실제 업무에서 나타나는 효과이므로 종료 승인과 별도로 추적합니다.

이 단원은 설명 → 자료 조회 → 예제 → 직접 확인 → 검토·수정 → 다음 업무 순서로 진행합니다. 웹 입력은 필요하지 않습니다. 문서를 작성할 때는 양식을 내려받고 같은 문서의 버전을 이어 갑니다.

## 단원 본문: 업무를 차례로 이해하기

약속한 요구부터 시험·현업 인수·운영 이관·계약 대조까지 증거를 연결하고, 프로젝트 종료 이후 남을 책임과 편익 측정을 인계합니다.

가져올 것: 현재 적용되는 승인 요구와 기준선, 변경 이력을 찾을 수 있다. / 품질계획·검사·결함 기록과 계약 조건이 정리되어 있다. / 검증·인수·종료 승인과 운영 책임을 다른 역할로 설명할 수 있다.

마치면 할 수 있는 일: 요구별 시험 증거와 실제 결과를 대조하고 검증·인수를 구분한다. / 운영 절차·지원·보증·자원·재무의 잔여 책임을 확인한다. / 종료 승인 조건과 문서 이력을 보존하며 편익의 후속 측정을 인계한다.

### 1. 완료라는 말을 네 가지 판단으로 풀어 읽기 (S4)

개발팀이 결과물을 전달했고 QA는 시험 기록을 정리했습니다. 이제 PM에게 “프로젝트가 끝났나요?”라는 질문이 옵니다. 답하기 전에 어떤 완료를 묻는지 나누어야 합니다. 코드를 납품한 상태, 품질 조건을 검증한 상태, 현업이 받아들인 상태, 조직이 프로젝트 종료를 승인한 상태는 서로 다른 근거와 권한을 가집니다.

| 판단 | 묻는 질문 | 주요 책임과 문서 |
|---|---|---|
| 검증 | 결과가 정한 조건을 충족하는가 | 정유나 시험 증거, D20 |
| 인수 | 현업이 약속한 결과를 받아들이는가 | 박다은 인수, D12 |
| 운영 이관 | 앞으로 누가 안전하게 사용·지원하는가 | 운영·기술·보안 창구와 절차 |
| 프로젝트 종료 | 기록·계약·자원·잔여 책임이 정리됐는가 | 윤서진 종료 승인, D07 |

보안 확인은 오수빈의 확인 범위를 별도로 연결합니다. QA가 제품 시험을 통과시켰다고 현업 인수나 프로젝트 종료 서명을 대신할 수는 없습니다. PM은 각 담당자가 확인한 증거를 모으고 서로 빠진 조건이 없는지 대조해 종료 판단을 가능하게 합니다.

종료보고서는 새로운 성과를 만들어 내는 문서가 아닙니다. 이미 수행한 시험·검토·인수·이관과 남은 의무를 읽기 쉽게 연결합니다. 사용 이후 나타날 업무 개선 효과는 별도 측정이 필요할 수 있습니다. 프로젝트를 종료할 수 있는 상태와 사업 편익이 입증된 상태를 구분하면 “종료했다”는 이유로 아직 측정하지 않은 성공을 선언하는 실수를 피할 수 있습니다.

### 2. 승인 요구에서 시험·계약·운영 자료까지 따라가기 (S4)

자신의 최신 D09를 펼치고 요구별로 연결된 시험을 확인합니다. 원천은 S15의 세부 시험, S13의 최종 집계, S14의 운영 매뉴얼·복구 절차, S21의 종료 인계 회의 순서로 읽으세요. 변경으로 추가된 요구도 현재 승인 범위에 들어 있으므로 최초 요구만 검사하고 끝내지 않습니다. D18의 계획과 D20의 결함·재시험 이력도 함께 둡니다.

| 조회 위치 | 확인할 자료 | 주의할 점 |
|---|---|---|
| ERP 검증 결과 | 요구·시험별 시도·통과·치명결함 | 집계만으로 세부 조건을 생략하지 않음 |
| S15와 S13 | 권한·로그·운영 시연·다운로드 증거 | 기대결과와 실제 결과를 비교 |
| 구매 상세 | 발주→검수→청구→지급 연결 | 같은 거래 금액을 중복 합산하지 않음 |
| S14·S21 | 절차·복구·보증·자원·편익 인계 | 지급 완료와 모든 책임 종료를 구분 |

ERP의 테스트 결과는 요약된 구조화 데이터입니다. R04의 통과 수 옆에는 어떤 접근이 허용 또는 차단되어야 하는지, 로그에 무엇이 남아야 하는지 원문을 붙여 이해합니다. R05는 운영자 수만 아니라 각자가 표준 업무를 독립 수행했는지와 매뉴얼·복구 절차 승인을 확인해야 합니다.

금액을 대조할 때는 프로젝트 원가와 공급사 지급을 별도로 읽습니다. 프로젝트 전체 원가 안에는 외주 비용이 이미 포함되어 있습니다. 계약 금액을 전체 원가에 다시 더하지 마세요. 원천의 기준일과 전표까지 확인한 범위를 기록하고, 비용·청구·지급 차이가 있다면 각각 어떤 미결 상태를 의미하는지 나누어 설명합니다.

### 3. R02 한 행에서 검증과 인수의 차이를 작성하기 (S4)

부분 예제로 R02를 D12에 연결해 봅니다. R02의 목표는 제공된 거래의 일치·불일치를 정확하게 분류하는 것입니다. S15에는 480거래 중 468건의 금액 일치와 12건의 차이를 올바르게 분류한 증거가 있습니다. 따라서 차이가 있는 거래가 남아 있다는 사실만으로 자동 대사 기능을 불합격이라고 판단하면 요구를 잘못 읽은 것입니다.

| D12의 R02 항목 | 부분 작성 예시 | 확인 범위 |
|---|---|---|
| 약속한 기준 | 제공된 480거래의 일치·불일치 정확 분류 | 승인된 요구와 대조 |
| 시험 증거 | T02, S15의 분류 결과와 S13 집계 | QA 검증 근거 |
| 인수 연결 | 박다은의 AT01 확인 범위에 포함되는지 대조 | 현업 인수는 별도 결정 |

이 작성 예시는 표 한 행의 연결을 보여 줍니다. 나머지 요구는 직접 원천을 읽고 채우세요. “통과”라는 말만 반복하지 말고 어떤 조건을 무엇으로 확인했는지 적습니다. R06의 데이터 결과와 권한·로그 조건, R05의 독립 수행과 절차 문서는 요약 숫자 하나로 모두 표현하기 어려우므로 상세 증거 위치를 함께 남깁니다.

D20에서는 최종 통과 결과가 나와도 최초 실패 기록을 보존합니다. DF01의 발견·영향·보완 지시·재시험·최종 상태를 시간순으로 연결해야 어떤 문제를 어떻게 해결했는지 알 수 있습니다. 과거 실패를 최종 합격 숫자로 덮어쓰면 품질 판단의 경로가 사라집니다. 검증 증거를 현업에 넘긴 다음 AT01과 SC01을 각자의 확인 범위로 기록하고, 이를 종료 조건 확인에 사용합니다.

### 4. 검토자별 질문으로 종료 초안의 빈칸 찾기 (S4)

다음 대화는 S13~S15·S21을 적용하는 교육용 검토 상황 예시입니다. 새로운 승인이나 보증 조건을 만들어 내는 회신은 아닙니다. 실제 원천에 적힌 사실과 자신의 D07·D12·D29가 일치하는지 확인하는 데 사용하세요. 검토자는 모두 같은 문서를 같은 관점으로 읽지 않습니다.

| 역할별 교육용 회신 | 학생이 대조할 내용 | 남길 기록 |
|---|---|---|
| 정유나·QA | “최종 합격만 남기고 최초 실패를 지웠나요?” | D20 실패·보완·재시험 이력 |
| 박다은·운영 | “매뉴얼과 복구 절차를 누가 이어받았나요?” | D12 인수와 운영 이관 |
| 강태훈·구매 | “잔금이 없으면 보증 창구도 닫는 건가요?” | D29 지급·보증 책임 분리 |
| 최민석·재무 | “미사용 자금을 사업 편익으로 썼나요?” | D07 자금 해제와 효과 측정 구분 |
| 윤서진·스폰서 | “종료 뒤 남는 업무의 책임자는 누구인가요?” | 잔여 책임·기한·보고 경로 |

운영 이관에서는 “매뉴얼 전달”만 확인하지 않습니다. 정산 오류가 생겼을 때 중단·보고·로그 보존·수작업 복구·이중지급 방지·재개 판단을 누가 맡는지 S14에서 따라가 보세요. 실제 시스템을 조작하거나 송금을 실행하는 실습이 아니라, 그 절차를 운영 담당자가 재현할 수 있는지 문서로 확인하는 과정입니다.

자원은 운영에 넘길 것과 프로젝트에서 해제할 것을 구분합니다. S21의 QA 환경 인계, 임시계정 해제, 운영 계정 유지, 프로젝트 배정 해제와 이후 지원 창구를 대조하세요. 코드와 계약 금액만 정리하고 사람·계정·지원 책임을 남겨 두면 종료 후 운영이 누구에게 요청해야 할지 알기 어렵습니다.

### 5. 사업 효과를 앞당기지 않고 종료 승인 조건에 맞게 수정하기 (S4)

종료 초안을 수정할 때 완료 사실과 향후 책임을 한 문장에 섞지 마세요. S21의 AP03은 인수·보안·계약 대조·잔여 책임 인계를 확인한 종료 승인입니다. 모든 장기 효과가 이미 검증됐다는 뜻이 아닙니다. 승인 문서에는 무엇이 확인됐고 무엇이 운영으로 넘어갔는지가 함께 보여야 합니다.

| 수정 전 | 수정 후의 방향 | 원천 근거 |
|---|---|---|
| “첫 주 평균 65분이므로 60분 목표 달성” | 사전 관찰치와 종료 후 평가를 분리 | S13·S17·S21 |
| “지급채무 0이므로 외주 책임 종료” | 잔금과 30일 무상 보완 창구를 구분 | S19·S21 |
| “미사용 자금은 프로젝트 편익” | 자금 해제 대상과 운영 효과를 별도 기록 | S13·S21 |
| “최종 승인본을 이후 상황에 맞게 덮어쓰기” | 승인본 보존, 새 사실은 운영 기록에 추가 | S21 |

편익은 박다은이 종료 다음 영업일부터 정한 기간 동안 추적합니다. S21은 2월 1일부터 2월 26일까지 20영업일의 측정과 보고를 정합니다. 팀의 순대사 경과시간과 운영자별 투입시간은 별도 항목이며 합쳐서 목표 평균을 만들지 않습니다. 아직 제공되지 않은 미래 측정 결과를 성공 또는 실패로 채우지 말고 담당·기간·방법·보고처만 인계합니다.

보증 창구는 최종검수 이후 남는 책임으로 기록합니다. 지급 완료와 별도로 강태훈의 접수 경로와 무상 보완 기간을 운영에 넘깁니다. 마지막으로 자신의 D07에 AP03의 승인 조건과 문서 ID·버전·승인일·잔여 책임을 연결합니다. 학생의 문서가 실제 회신 조건을 빠뜨렸다면 그 누락을 보완해야 하며, 승인 기록이 있다는 이유로 빈 종료보고가 자동 완성되지는 않습니다.

### 6. 다른 사람이 업무를 이어받을 수 있는지 최종 확인하기 (S4)

이제 R02 예제를 제외한 요구의 검수·인수 기록을 독립 작성하고, 계약·재무·운영·자원 항목을 완성하세요. 다른 사람이 프로젝트 폴더를 처음 열었을 때 어떤 버전을 읽고 누구에게 후속 업무를 요청해야 하는지 알 수 있어야 합니다. 자료를 많이 첨부하는 것보다 필요한 결정을 뒷받침하는 근거를 다시 찾을 수 있게 연결하는 것이 중요합니다.

| 최종 점검 | 찾아갈 연결 | 인계받을 업무 |
|---|---|---|
| 약속을 모두 확인했는가 | D09→D18→D20→D12 | 현업 운영과 인수 이력 |
| 계약·돈을 정리했는가 | D27·D29→검수·청구·지급·전표 | 보증과 미결 책임 관리 |
| 안전하게 이어서 운영할 수 있는가 | 운영·복구 절차와 자원·계정 인계 | 운영·기술·보안 창구 |
| 종료 뒤 무엇을 더 확인하는가 | D07→편익 측정·보고 계획 | 운영 책임자의 후속 측정 |

최종 비용과 지급을 각각 대조해 문서에 기록하고, 미사용액이 어느 예산 범위와 비교한 값인지 확인합니다. 관리예비비를 포함한 총자금과 원가기준선을 같은 숫자로 취급하지 않습니다. 계약의 누적 검수·청구·지급이 같은 경우에도 그 금액을 더해 비용을 부풀리지 않습니다.

자기 점검의 마지막 질문은 “내가 내일부터 자리를 비워도 다음 담당자가 진행할 수 있는가”입니다. 남은 업무에는 담당·기한·확인 방법이 있고, 완료한 업무에는 원천·판정·승인 이력이 있어야 합니다. D04의 교훈에는 적용 조건과 확인된 효과, 아직 검증하지 못한 내용을 나누어 남깁니다. 이 연결을 설명할 수 있다면 Level 1의 목표인 자료에 근거한 착수부터 종료까지의 문서화 업무를 한 번 수행한 것입니다. 실제 수업에서는 이어서 다른 요구 항목을 도움 없이 완성할 수 있는지 확인합니다.

다음 업무: 종료 승인본과 관리 이력을 보존하고 운영·지원·보증·편익 측정의 책임과 확인 방법을 다음 담당자에게 인계합니다.

### 이번 업무를 이해하기

최종 합격만 남기면 어떤 결함을 어떻게 해결했는지 잃습니다. 기대 결과와 실제 결과를 비교하고 최초 실패·조치·재시험을 하나의 이력으로 연결합니다.

### 개념을 한 단계 더 이해하기

품질 통제는 기대 결과와 실제 결과를 대조해 인도물의 상태를 확인합니다. 최초 실패·수정·재시험·최종 판정은 하나의 결함 이력으로 연결됩니다. 최종 합격만 남기면 무엇이 잘못됐고 어떻게 해결했는지 잃으므로 추후 운영 문제가 생겼을 때 판단 근거가 줄어듭니다.

### 가져올 문서와 현재 상태

D18 품질계획, D19 절차점검과 7단원에서 시작한 D20 최초 결함 기록을 가져옵니다.

### ERP 목록과 문서 연결하기

ERP에서 「검증 결과」 → 「초기화」 → 정확히 일치 항목 「test_id」 → 값 「T04」 → 「조회」 순서로 진행합니다.

tested는 시험 수, passed는 통과 수, critical_open은 미해결 중대 결함 수입니다. req_id와 source_id로 요구·근거를 찾고 D20에 대조합니다. T02도 직접 확인하며 정확 분류와 모든 거래의 금액 일치를 혼동하지 않습니다.

조회 결과가 다르면 현재 자료 단계와 남은 검색조건을 먼저 확인하세요. 원천 ERP는 읽기 전용이며 작성은 내려받은 문서에서 합니다.

### 자료를 찾아 읽기

2. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S12 → 조회 → 목록의 S12 상세를 엽니다. 읽을 부분: AP02 승인 조건, 후속 작업·재시험·수신확인. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

3. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S13 → 조회 → 목록의 S13 상세를 엽니다. 읽을 부분: 최종 비용·검수·인수·종료 근거. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

4. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S15 → 조회 → 목록의 S15 상세를 엽니다. 읽을 부분: 요구별 인수시험과 운영자 시연 증거. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

### 검토 의견으로 수정하기

초안 “최종 통과로 최초 실패 덮어쓰기” → 수정 이력이 사라집니다 → 실패·수정·재시험·최종 판정을 각 날짜와 증거로 보존합니다.

검토 역할: 정유나. 최종 합격으로 최초 실패를 덮어썼나요? 수정·재시험 이력과 최종 판정을 함께 보관하세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

### 다음 업무로 넘기기

D20 검사·결함대장의 현재 버전과 근거를 보존합니다. 이 문서를 다시 사용할 때 현재 상태가 초안·분야 검토·승인 중 무엇인지 확인합니다. 문서 본문은 한 번 작성하고 수행표에는 위치만 남깁니다.

### 내 문서에 적용하고 다음 사람에게 넘기기

D20의 각 결과에 요구·시험 ID와 날짜·증거를 붙입니다. 합격과 미실시를 구분하고 조건별 검증 결과를 현업에 전달합니다. QA의 검증은 다음 D12 인수 판단의 입력이며 QA가 현업의 수락 결정을 대신하는 것은 아닙니다.

### 생각을 확인하기

재시험에 합격한 결함의 최초 실패 기록은?

1. 혼동되니 삭제한다.

### 이번 업무를 이해하기

검증은 정해진 조건을 충족하는지 확인하는 일이고 인수는 현업이 결과를 받아들이는 결정입니다. 코드를 받았다는 사실만으로 운영할 준비가 끝났다고 볼 수 없습니다.

### 개념을 한 단계 더 이해하기

초안 “미사용 예산이 사업 편익이며 목표 달성” → 자금 잔액과 실제 효과를 혼동했습니다 → 잔액은 해제 대상으로, 편익은 담당·측정 기간·보고일로 인계합니다.

검토 역할: 윤서진. 첫 주65분을 목표 달성 또는 미사용 예산을 편익으로 적었나요? 프로젝트 종료와 사후 편익 검증을 분리하세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

### 다음 업무로 넘기기

D07 종료보고의 현재 버전과 근거를 보존합니다. 이 문서를 다시 사용할 때 현재 상태가 초안·분야 검토·승인 중 무엇인지 확인합니다. 문서 본문은 한 번 작성하고 수행표에는 위치만 남깁니다.

### 내 문서에 적용하고 다음 사람에게 넘기기

D07에 종료 조건별 근거와 남은 책임의 수신자를 적습니다. 편익을 누가 언제 측정·보고하고 보증 문의를 어디로 넘길지 확인한 뒤 교육용 종료 승인 조건과 대조합니다. Level 1의 마지막 확인은 첫 헌장 목적부터 종료 증거까지 한 연결을 자신의 말로 설명하는 것입니다.

### 단원 마무리

D20 검사 이력, D12 인수, D29 계약대조와 보증 인계, D07 종료본을 제출합니다. AP03을 연결하고 편익 측정일과 담당자를 운영에 인계합니다. 아직 제공되지 않은2월 결과는 공란으로 남깁니다.

### 생각을 확인하기

종료 후 측정할 편익 목표는 종료보고에서 어떻게 다루나요?

1. 프로젝트가 끝났으니 자동 달성으로 쓴다.
2. 측정 책임·기간·보고 경로를 인계하고 아직 검증되지 않은 효과를 구분한다.
3. 종료 후 일은 모두 삭제한다.

먼저 선택한 이유를 자신의 말로 설명해 보세요.

자기확인 해설: 2번. 결과물 인도와 편익 실현 검증은 시점이 다를 수 있습니다. 프로젝트가 끝나도 효과를 확인할 책임과 방법은 이어져야 합니다.
