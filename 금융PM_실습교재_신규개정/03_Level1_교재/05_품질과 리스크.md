# 05. 품질과 리스크

정유나는 “무엇을 검사해야 끝났다고 할 수 있나요?”, 이현우는 “어떤 일이 틀어질 수 있나요?”라고 묻습니다. 합격 기준과 불확실성을 함께 설계하세요.

품질 계획은 무엇을 어떤 방법으로 검사해 합격이라고 할지 미리 정하는 일입니다. 품질 관리는 좋은 결과가 나오도록 작업 절차를 개선하고, 품질 통제는 실제 결과를 검사합니다. 리스크는 아직 발생하지 않은 불확실 사건이며 이미 발생한 문제는 이슈로 다룹니다. 정성 분석은 비교 척도로 우선순위를 정하고, 정량 분석은 확률과 금액 같은 수치를 사용합니다. 기대손실은 여러 가능성의 가중평균이지 확정 지출이 아닙니다.

이 단원은 설명 → 자료 조회 → 예제 → 직접 확인 → 검토·수정 → 다음 업무 순서로 진행합니다. 웹 입력은 필요하지 않습니다. 문서를 작성할 때는 양식을 내려받고 같은 문서의 버전을 이어 갑니다.

## 좋은 결과의 조건과 불확실성을 함께 설계합니다

품질은 개발 후 결함 수를 세는 일로만 끝나지 않습니다. 어떤 결과를 합격으로 볼지 미리 정의하고, 좋은 결과를 만드는 절차가 작동하는지 확인해야 합니다. 리스크(Risk)는 아직 발생하지 않은 사건이며, 이미 발생한 문제는 이슈(Issue)로 다룹니다. 둘은 연결되지만 상태와 조치가 다릅니다.

## 정성과 정량은 다른 질문에 답합니다

정성 분석은 먼저 주의를 기울일 대상을 비교하고, 정량 분석은 불확실성이 금액이나 일정에 미칠 영향을 계산합니다. 이 교재의 점수 규칙은 가상회사의 내부 규칙입니다. 점수표를 확률의 단위처럼 사용하거나 기대손실을 반드시 지출할 금액처럼 설명하지 않도록 계산의 질문부터 적습니다.

## 분석 결과는 업무를 바꿔야 합니다

위험 표를 완성했어도 담당자가 수행할 조치·기한·트리거가 없으면 실제 대응은 시작되지 않습니다. 예방조치는 일정과 자원에, 발생 시 대응은 예비비와 의사결정 경로에 연결합니다. 이 단원을 마치면 3·4단원 초안으로 돌아가 대응이 이미 포함된 비용인지, 별도 작업을 추가해야 하는지 확인합니다.

### 이번 업무를 이해하기

품질계획은 좋은 제품이라는 추상적인 말을 검사 방법으로 바꾸는 작업입니다. 무엇을 몇 건 검사하고, 누가 어떤 결과를 합격으로 볼지 적습니다. 지금은 계획이므로 실제 통과 수를 적지 않습니다.

### 개념을 한 단계 더 이해하기

품질 기준에는 무엇을 측정하는지와 어떤 결과를 합격으로 보는지가 함께 있어야 합니다. “정확도 100%”도 분모가 거래 건수인지 금액인지 분류 결과인지에 따라 뜻이 달라집니다. 제품 검사 기준과 좋은 결과를 만들기 위한 절차 점검은 나눠 설계합니다. 둘 중 하나만 있어서는 품질관리가 완성되지 않습니다.

검토 역할: 정유나. 예외가0건이어야 합격이라고 썼나요? 예외를 정확히 찾고 필수정보를 남기는 것과 사업상 차이 자체가 없는 것은 다릅니다. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

### 다음 업무로 넘기기

D18 품질계획·지표의 현재 버전과 근거를 보존합니다. 이 문서를 다시 사용할 때 현재 상태가 초안·분야 검토·승인 중 무엇인지 확인합니다. 문서 본문은 한 번 작성하고 수행표에는 위치만 남깁니다.

### 내 문서에 적용하고 다음 사람에게 넘기기

D18에서 요구별 측정 대상·단위·표본·합격 기준·담당·시점을 완성합니다. 실패했을 때 결함 등록→보완→재시험→인수 인계가 어떻게 이어질지도 적으세요. 아직 검사하지 않은 결과를 합격으로 표시하지 않고 검사할 준비가 됐는지를 확인합니다.

### 다음에 이어 할 일

위험을 판단하고 다시 확인할 규칙 정하기 단계로 이어집니다. 현재 작성한 문서의 항목·근거를 가져가세요. 자료 단계가 바뀌면 먼저 현재 기록을 보존합니다.

### 생각을 확인하기

품질지표에 “정확도 100%”만 적으면 부족한 이유는?

1. 숫자가 너무 높기 때문이다.
2. 측정 대상·분모·방법·판정 조건이 빠질 수 있기 때문이다.
3. 품질은 정성 의견으로만 평가하기 때문이다.

먼저 선택한 이유를 자신의 말로 설명해 보세요.

자기확인 해설: 2번. 백분율은 무엇을 세었는지가 있어야 의미가 있습니다. 금액 일치와 대사 분류 정확성처럼 다른 대상을 같은 지표로 섞지 않습니다.

## 2. 위험을 판단하고 다시 확인할 규칙 정하기

없음·K02만·동시 발생을 계산해 확률 합이 1인지 확인하세요. 각 손실을 예비비 10백만원과 비교하고 감당하지 못하는 경우를 설명합니다.

### 검토 의견으로 수정하기

초안 “예비비를 뒀으니 비용 위험 없음” → 평균과 최악을 혼동했습니다 → 발생 경우별 부족 가능성과 추가 승인 경로를 남깁니다.

검토 역할: 최민석. 기대손실을 최악손실 또는 반드시 지출할 금액으로 설명했나요? 네 시나리오와 예비비를 다시 비교하세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

### 다음 업무로 넘기기

D26 정량리스크 분석의 현재 버전과 근거를 보존합니다. 이 문서를 다시 사용할 때 현재 상태가 초안·분야 검토·승인 중 무엇인지 확인합니다. 문서 본문은 한 번 작성하고 수행표에는 위치만 남깁니다.

### 내 문서에 적용하고 다음 사람에게 넘기기

D26에서 각 시나리오 손실을 제안된 우발예비비와 나란히 놓습니다. 기대손실 비교와 큰 손실을 감당하는지의 질문을 따로 답하세요. 예비비가 모든 위험을 보장한다는 문장 대신 어떤 경우에서 부족하고 어떤 판단이 필요한지 권고합니다.

### 다음에 이어 할 일

위험 대응을 담당자의 작업으로 바꾸기 단계로 이어집니다. 현재 작성한 문서의 항목·근거를 가져가세요. 자료 단계가 바뀌면 먼저 현재 기록을 보존합니다.

### 생각을 확인하기

기대손실이 예비비보다 작으면 모든 발생 시나리오를 감당하나요?

1. 아니요, 평균 노출과 각 시나리오의 최대 손실은 다르다.
2. 예, 기대금액은 최악의 비용이다.
3. 예, 독립 가정이면 큰 손실은 발생하지 않는다.

먼저 선택한 이유를 자신의 말로 설명해 보세요.

자기확인 해설: 1번. 기대금액은 가중평균입니다. 낮은 확률의 큰 손실은 평균보다 클 수 있으므로 네 시나리오를 각각 예비비와 비교합니다.

## 6. 위험 대응을 담당자의 작업으로 바꾸기

자료 단계: S1. 관련 프로세스: 11.5.

[S07 품질·리스크 워크숍 원문](../02_원천문서/S1/S07.md) · [S19 계획 보충: 자금·계약·리스크 운영 조건](../02_원천문서/S1/S19.md)

### 이번 업무를 이해하기

위험에 주의하자는 말만으로는 실행이 시작되지 않습니다. 사전 조치·담당·기한·완료 증거와, 실제 발생 시 사용할 대응을 구분합니다. 예방비용이 기존 공수에 포함되는지도 확인합니다.

### 개념을 한 단계 더 이해하기

대응전략의 이름만 쓰면 담당자가 행동할 수 없습니다. 예방조치, 책임자, 기한, 완료 증거, 발생을 알리는 트리거, 발생 시 조치를 함께 정해야 합니다. 위험 소유자는 관찰과 대응을 연결하지만 모든 작업을 혼자 수행해야 한다는 뜻은 아닙니다. 필요한 작업은 일정·자원계획에 들어가야 합니다.

### 가져올 문서와 현재 상태

D25,D26

### 자료를 찾아 읽기

1. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S07 → 조회 → 목록의 S07 상세를 엽니다. 읽을 부분: 품질 기준, K01/K02 확률·영향·평가 규칙. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

2. ERP의 원천 문서 메뉴에서 초기화 → 검색어 S19 → 조회 → 목록의 S19 상세를 엽니다. 읽을 부분: 지급·계약·보증 조건과 예방비용·예비비 운영. 확인한 사실의 단위·날짜·담당자를 함께 읽습니다.

찾지 못하면 현재 자료 단계와 이전 검색조건을 확인하세요. 파일로 읽을 때는 같은 ID의 원천 문서를 사용합니다. SQL은 선택 경로입니다.

### 근거를 판단으로 바꾸는 과정

S07의 표본검증과 환경 사전점검을 각각 어떤 사건을 줄이기 위한 일인지 연결합니다. S19에서 그 예방비용이 기존 공수에 포함됐는지 확인하세요. 이미 포함된 비용을 새 예방예산으로 다시 더하거나, 아직 시행하지 않은 대응을 완료 상태로 쓰지 않습니다.

### 함께 따라 하는 예제

K01의 사전 표본검증은 이현우가 수행할 작업으로 연결합니다. D25의 계획 부분에 조치와 확인 증거를 적고 완료일은 아직 비웁니다. S19에 따라 이미 포함된 예방 공수를 예비비에 다시 더하지 않습니다.

### 문서에 반영하기

D25 리스크등록부·보고서 양식을 사용합니다.

1. D25에 사전 조치·책임·완료 증거·기한·트리거를 추가한다.

2. S19에 따라 기존 공수에 포함된 예방비용과 발생 후 사용할 예비비를 구분한다.

3. 계획 시점의 잔여 위험은 재평가 예정이라고 적고 D14/D17의 영향 검토로 돌아간다.

### 직접 확인해 보기

K02의 트리거·책임·대응을 작성한 뒤 D14와 D17로 돌아가 일정과 비용의 포함 여부를 확인하세요. 변경이 없다면 그 대조 근거를 남깁니다.

### 검토 의견으로 수정하기

초안 “대응 계획 작성=조치 완료” → 실행 증거가 없습니다 → 계획과 실제 실행일·확인자를 나누고 7단원에서 갱신합니다.

검토 역할: 이현우. 아직 점검하지 않은 예방조치를 완료로 표시했나요? 계획된 조치와 실행 증거의 날짜를 분리하세요. 이미 충족한 경우 문장의 근거를 확인하면 됩니다. 오류를 일부러 만들 필요는 없습니다.

### 다음 업무로 넘기기

D25 리스크등록부·보고서의 현재 버전과 근거를 보존합니다. 이 문서를 다시 사용할 때 현재 상태가 초안·분야 검토·승인 중 무엇인지 확인합니다. 문서 본문은 한 번 작성하고 수행표에는 위치만 남깁니다.

### 내 문서에 적용하고 다음 사람에게 넘기기

D25에서 대응 한 건을 작업지시처럼 읽어 보세요. 담당자가 무엇을 언제 완료하고 어떤 증거를 남길지 알아야 합니다. D14·D17로 돌아가 기간·예비비와의 연결을 확인하고 실행 단원에서 실제 수행을 대조할 수 있도록 상태를 계획으로 남깁니다.

### 단원 마무리

품질지표별 측정법과 위험 네 시나리오 계산을 제출합니다. 예방조치·책임·트리거를 기록하고 일정·예산 단원으로 돌아가 비용·기간 포함 여부를 확인한 후 검토 이력을 남깁니다.

### 생각을 확인하기

예방조치가 기존 설계·QA 공수에 포함되었다면?

1. 조치를 기록하지 않는다.
2. 같은 비용을 다시 더해 예산을 늘린다.
3. 조치는 추적하되 포함 조건을 명시해 비용 중복을 막는다.

먼저 선택한 이유를 자신의 말로 설명해 보세요.

자기확인 해설: 3번. 별도 추가 비용이 없다고 관리할 작업이 없는 것은 아닙니다. 실행 책임과 증거를 남기면서 기존 비용에 포함된 사실을 표시합니다.
