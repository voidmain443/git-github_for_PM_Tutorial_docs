# Level 1 개선항목 처리 결과

기준: 2026-09-23. [이전 검토](2026-09-22_남은작업과_학습성_검토.md)의 R01~R15와 A~G를 기준으로 반영했다. 최신 검증 수치와 배포 범위는 [현재 검증 상태](현재_검증상태.md)를 확인한다.

**A~F의 집필·양식·조회·화면 개선을 반영했다. G는 독립 배포 실행까지 확인했으며, 실제 입문자 파일럿과 그 결과에 따른 수정·시간 편성이 남았다.** 자동 검사 통과를 학습 효과 검증이나 Level 1의 최종 교육 완료로 표시하지 않는다.

## 1. 학생이 진행하는 방식

1. 0단원에서 회사의 일, 인물과 권한, 정산·대사, 회사 현금과 프로젝트 돈의 차이를 읽는다. 한 건을 함께 조회하고 다른 건을 직접 확인한다.
2. 1단원에서 D01 헌장 초안을 만든다. 사업 필요 → 관련 인물 → 목표 → 상위 요구·인수 → 경계 → 자금 → 일정 → 권한 → 가정·종료 책임 → 검토·수정 → 승인 조건 대조 순서로 진행한다.
3. 2~6단원에서 요구·WBS·활동·자원·일정·원가·품질·위험·조달·소통을 연결한다. 아직 작성하지 않은 문서를 이미 완성된 입력처럼 요구하지 않는다. 뒤에서 확인한 위험·계약 조건은 앞의 일정·예산 초안으로 돌아가 반영한다.
4. 7단원에서 분야 계획을 통합 대조하고 승인 자료를 연다. 승인 후 킥오프·작업지시·실행 증거·팀과 이해관계자 관리를 이어 간다.
5. 8단원에서 현재 성과와 변경 대안을 분석하고 승인 전 권고안을 보존한다. 다음 자료팩의 승인 결과를 대조한 뒤 관련 문서와 기준선을 함께 갱신한다.
6. 9단원에서 품질 증거 → 현업 인수 → 계약·지급·잔여 책임 → 운영이관·종료 순서로 확인한다. 종료 후 편익 측정과 보증 책임은 인계한다.

웹에는 답을 입력하지 않는다. 안내를 읽고 ERP로 확인한 뒤 내려받은 실제 PM 문서를 작성한다. 워크북은 문서ID·항목·버전·검토 위치를 가리키므로 본문을 다시 복사하지 않는다. 목차는 자유롭게 볼 수 있고 미래의 사실·예제는 해당 자료팩에서 공개한다.

## 2. 지적사항별 처리

| ID | 반영한 개선 | 확인 근거·남은 확인 |
|---|---|---|
| R01 | 0~9단원을 공통 읽기 화면으로 전환. 웹 작성 칸·체크에 따른 이동 제한 제거. 기존 작성 기록은 삭제하지 않고 내보내기 제공. | 10개 단원 화면 검사, 읽던 위치·기존 기록 보존 확인. |
| R02 | ERP 첫 사용 안내, 0단원, 워크북을 별도 문서 작성 방식으로 통일. 없어진 버튼을 누르라는 문구 제거. | 생성 원고 및 화면 안내 대조, 옛 버튼 문구 검사. |
| R03 | 9단원을 품질 통제 → 범위 인수 → 조달 대조 → 종료 순서로 수정. | D20·D12·D29를 작성한 뒤 종료보고에 사용. |
| R04 | 자원 계획·수량 확인을 기간 계산 앞에 배치. 위험 문서는 후속 갱신으로 표시. D05/D20을 처음 시작할 위치 명시. | 단계별 가져올 문서와 현재 상태, 인계 안내. |
| R05 | D14를 활동 정의·선행/기간·네트워크 계산·날짜·버전의 다섯 표로 구성. 강사용에 전진·역진·달력 대조 추가. | 요구한 작성 칸 존재 및 계산·날짜 검사. |
| R06 | D17의 실제 예산 구조와 월별 비용·현금 표를 기준으로 설명. 비용 인식과 현금 지급을 구분하는 예제 제공. | 4단원 예제·양식·원천 조건 대조. |
| R07 | 가정 실습 단계에 A01 직접 다운로드와 작성 안내 추가. | 실제 웹 다운로드 노출 확인. |
| R08 | 종료의 S14, 지식관리의 S20 등 본문에서 사용하는 원천을 해당 단계에 연결. | 단계별 원천 존재·공개시점 검사와 문서 열기 확인. |
| R09 | 모든 프로세스에 업무 설명·부분 예제·직접 수행·검토 및 수정 이유 추가. 헌장은 항목별 12단계로 세분화. | 69개 읽기 단계, 49개 수행 연결. 이해도는 파일럿에서 확인. |
| R10 | 원천별 읽을 부분·검색 순서·작성 위치 안내. 담당자·요구·자원·예산·성과·시험·조달에 13개 구체적 조회 연습 추가. | 해당 시점의 실제 데이터로 조건 검증. 승인 전 기준선 0건의 의미 설명. |
| R11 | 설치된 자료팩을 화면에서 전환. 미래 단계 목차와 본문 공개를 분리. | 한 서버에서 S0→S4 전환, 미설치 팩 거부, 미래 예제 비공개 확인. |
| R12 | 워크북을 실제 산출물의 위치를 가리키는 수행표로 개정. | 같은 문서 본문을 웹·워크북에 중복 작성하지 않도록 안내. |
| R13 | 49개 수행별 핵심 오류·완료 증거와 입문자 관찰지 추가. | **평가 기준 집필 완료, 실제 학생 수행 검증은 미실시.** |
| R14 | 현재 검증 색인 작성, 예전 화면·검사 결과는 이력으로 구분. 실제 ZIP 실행 검사 추가. | 현재_검증상태.md와 최신 JSON 결과. |
| R15 | 목차를 학생이 하는 일 중심으로 개정. 코드는 보조 정보로 배치. 새 예제는 수치의 단위·기준일·계획/실적을 함께 설명. | 실제 입문자가 어려워하는 용어·문장은 관찰 후 재편집. |

## 4. 남은 작업의 실제 순서

| 순서 | 해야 할 일 | 완료 판정 |
|---|---|---|
| 1 | 실제 입문자가 시작팩만으로 0~1단원을 수행. 설명하지 말고 먼저 막히는 위치 관찰. | 헌장의 핵심 사실을 출처와 연결하고 검토 후 수정 이유를 설명. 강사의 새로운 사실 보충이 필요하지 않음. |
| 2 | 관찰에서 드러난 문장·자료·양식 결함 수정 후 같은 과제 재수행. | 원인이 된 설명으로 스스로 다시 진행 가능. 학생 오답과 자료 결함을 구분. |
| 3 | 2~4단원 연결, 이어 전체 과정 수행. | 요구→WBS→일정·예산→실적→검수의 연결을 학생이 재현. 미승인 변경·비용 중복·성급한 종료 등의 핵심 오류 해소. |
| 4 | 조회·작성·검토 시간을 반영해 부트캠프 수업 편성. | 설명·개인 실습·역할 검토·휴식 시간을 실제 관찰에 근거해 배분. |

Level 2~4는 기존 교육목표·진입조건·확장 규칙을 유지한다. 상세 시나리오와 데이터의 제작은 Level 1 파일럿 이후 진행한다.
