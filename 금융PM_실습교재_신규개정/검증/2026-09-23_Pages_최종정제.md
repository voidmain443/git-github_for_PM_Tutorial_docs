# 공개 웹 교재 최종 정제

대상: 금융PM_실습교재_신규개정 독립 패키지. 원천 회사·수치·학습 시점은 유지하고 공개 웹 사용성과 배포 방식을 정리했다.

## 학생에게 달라진 점

1. 시작 화면에서 교재 → 자료 조회 → 내 문서 작성의 순서와 10개 단원을 안내한다.
2. 각 단원에 배울 업무, 가져올 문서와 현재 상태, 마무리 산출물과 다음 사용처를 추가했다.
3. 원천 버튼에 문서 제목을 표시하고 자료실에서 빈 양식의 표를 미리 보거나 내려받을 수 있게 했다.
4. GitHub Pages에서 설치 없이 검색·상세·집계·CSV·SQL을 사용한다. 기존 SQLite 파일을 브라우저에서 직접 읽는다.
5. 자료 선택은 학생별 브라우저에 적용되고 같은 사이트의 다른 탭은 함께 갱신된다.
6. 현재 시점의 교재·워크북 PDF를 제공하고 강사용 완성 답안과 개인 기록은 웹 공개 목록에서 제외했다.

웹에는 학생의 답을 입력·제출하는 기능을 추가하지 않았다. 미래 시점 안내는 학습 순서이며 보안상 접근 제한을 뜻하지 않는다.

## 확인한 결과

| 범위 | 결과 |
|---|---|
| 자료·회계·집계 규칙 | 354/354 통과 |
| 학습 흐름·문서·시점 | 472/472 통과 |
| 읽기 단계·근거·조회 조건 | 790/790 통과 |
| 로컬 교재 브라우저 | 107개 통과 |
| GitHub Pages 방식의 브라우저 흐름 | 94개 통과 |
| 브라우저 SQLite와 로컬 ERP 비교 | 7개 시점, 431개 목록·상세·SQL 결과 일치 |
| 깨끗한 소스 재생성 | Git에 올릴 파일만 복사한 별도 폴더에서 DB·교재·PDF·정적 사이트 생성 성공 |
| 공개 파일 | 허용 목록만 생성; 강사용 파일·개인 실습 기록 없음 |

페이지 검사는 실제 저장소 이름이 붙는 경로에서 수행했다. 0단원 진입, 원천 문서, 한글 양식 다운로드, ST001 정확 조회, CSV, 다른 탭 갱신, 독립 학생의 시점, 미래 예제 표시, 인쇄본, 모바일을 확인했다. 잘못된 SQL·변경문을 거부하고 오래 걸리는 쿼리를 중단한 뒤 정상 조회가 회복되는지도 확인했다. 첫 화면과 단계 안내의 데스크톱·모바일 이미지를 시각 검토했다.

원본: [Pages 브라우저 검증](Pages_브라우저검증.json), [로컬 브라우저 검증](읽기교재_화면검증.json). 검사는 기술적 정합성과 사용 경로를 확인한다. 실제 초보 학습자의 이해도와 수행 시간은 별도 파일럿의 대상이다.

## 배포와 유지보수

워크플로는 자료 재생성 → 자동 검증 → 학생용 사이트 구성 → 브라우저 검증 → Pages 배포 순서다. PR에서는 검사만, main에서는 검사 성공 후 배포한다. 배포 운영과 재현 방법은 [운영 안내](../README_GitHub_Pages.md)를 따른다.

실제 배포 상태와 로그는 [GitHub Actions](https://github.com/voidmain443/git-github_for_PM_Tutorial_docs/actions/workflows/financial-pm-pages.yml)에서 확인한다. 다음 교육 개선은 0~1단원 실제 파일럿 → 오류 문장·자료 수정 → 전 과정 수행 → 시간 편성 순서다.
