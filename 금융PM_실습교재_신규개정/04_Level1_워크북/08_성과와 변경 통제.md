# 08. 성과와 변경 통제 - 문서 실습 안내

교재의 단계별 설명을 읽은 뒤 실제 산출물을 작성합니다. 웹에 다시 입력하거나 이 워크북에 본문을 중복 복사할 필요는 없습니다.

이번 단원의 결과: 기준일·단위·범위를 맞춰 성과지표를 계산하고 그 한계를 설명한다. / 기존 요구의 결함과 신규 범위를 구분해 변경 대안과 권고를 작성한다. / 승인 기록에 맞춰 관련 문서를 함께 갱신하고 이전 버전을 보존한다.

단원 본문 여섯 절을 읽은 뒤 아래 과제를 차례로 진행합니다. 시각화는 변경 대안을 비교해 승인받을 안을 상정하기 단계에서 이해가 필요할 때만 사용하며 필수 제출물이 아닙니다.

## 성과 숫자를 계산하고 비용 전망을 설명하기 (7.4)

검토: 초안 “EAC가 새 승인 예산” → 예측과 승인을 혼동했습니다 → D05에는 예측 가정으로, 기준선 변경은 D06 승인 경로로 분리합니다.

## 기존 요구의 결함과 새로운 범위를 구분하기 (5.6)

검토: 초안 “CSV는 단순 버그 수정” → 기존 요구에 없는 기능을 숨깁니다 → 새 기능의 영향 분석과 승인 여부를 별도로 관리합니다.

## 보고가 전달되고 이해됐는지 확인하기 (10.3)

검토: 초안 “참석률이 높으므로 모두 이해” → 이해 증거가 없습니다 → 확인 질문과 실행 여부를 추가로 확인합니다.

## 남은 위험을 재평가하고 계속 볼 항목 정하기 (11.7)

검토: 초안 “표본검증 통과이므로 확률 0” → 제공된 재평가와 다릅니다 → 실제 재평가 수치를 사용하고 대응의 한계를 설명합니다.

## 참여 상태를 날짜가 있는 증거로 평가하기 (13.4)

검토: 초안 “설명을 보냈으니 지원 상태” → 상대의 반응을 확인하지 않았습니다 → 관찰 증거와 다음 확인 행동을 나눕니다.

## 분야별 사실을 한 장의 성과보고로 연결하기 (4.5)

검토: 초안 “문제없이 진행 중” → 남은 오픈 조건을 숨깁니다 → 현재 상태와 판단을 막는 조건, 담당·기한을 구체적으로 보고합니다.

## 변경 대안을 비교해 승인받을 안을 상정하기 (4.6)

검토: 초안 “요청받았으므로 즉시 구현” → 기준선이 승인 없이 바뀝니다 → 영향 검토와 권고를 먼저 남긴 뒤 결정에 따라 관련 문서를 갱신합니다.

### 생각을 확인하기

새 기준선이 승인되면 과거 성과보고도 새 기준선으로 소급해 덮어쓰나요?

1. 아니요, 과거 기준과 기록을 보존하고 새 버전의 적용 시점을 명시한다.
2. 예, 최신 버전만 남기면 된다.
3. 성과가 좋아 보이는 버전을 임의로 고른다.

먼저 선택한 이유를 자신의 말로 설명해 보세요.
