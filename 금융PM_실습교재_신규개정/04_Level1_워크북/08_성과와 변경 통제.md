# 08. 성과와 변경 통제 - 문서 실습 안내

교재의 단계별 설명을 읽은 뒤 실제 산출물을 작성합니다. 웹에 다시 입력하거나 이 워크북에 본문을 중복 복사할 필요는 없습니다.

## 성과 숫자를 계산하고 비용 전망을 설명하기 (7.4)

사용 문서: D05 주간성과보고. 근거: S10.

확인할 수행: SV·CPI·SPI를 구하고 각 결과를 한 문장으로 해석하세요. BAC/CPI와 AC+(BAC−EV)의 EAC를 비교하며 효율이 계속되는지에 대한 가정을 적습니다. 계산은 S2의 기존 기준선으로 합니다.

검토: 초안 “EAC가 새 승인 예산” → 예측과 승인을 혼동했습니다 → D05에는 예측 가정으로, 기준선 변경은 D06 승인 경로로 분리합니다.

## 기존 요구의 결함과 새로운 범위를 구분하기 (5.6)

사용 문서: D09 요구사항·추적표. 근거: S03, S10, S11.

확인할 수행: S03의 기존 인수조건과 S11의 요청을 비교해 차이를 적으세요. 요청 때문에 영향을 받는 범위·시험·작업패키지를 검토하되 아직 기준선으로 표시하지 않습니다.

검토: 초안 “CSV는 단순 버그 수정” → 기존 요구에 없는 기능을 숨깁니다 → 새 기능의 영향 분석과 승인 여부를 별도로 관리합니다.

## 계획 일정과 현재 상태를 비교하기 (6.6)

사용 문서: D14 활동·일정표. 근거: S10, S11.

확인할 수행: D14에서 현재 기준선·실적·예측을 구분하세요. 변경 영향 후보는 D06에 연결하고 승인 후 갱신 단계에서 새 버전을 만듭니다.

검토: 초안 “SPI 부족분×전체 기간=지연일” → 달력 근거가 없습니다 → 네트워크·잔여 기간과 기술 추정에 근거해 날짜 영향을 설명합니다.

## QA 환경의 계획 수량과 실제 상태 확인하기 (9.6)

사용 문서: D21 자원계획·RACI. 근거: S06, S10.

확인할 수행: 환경 상세와 S10을 읽고 D21의 물적자원 표를 갱신하세요. 운영 인계 예정과 실제 인계 완료를 구분하고 임시 계정 해제는 종료 때 증거를 붙입니다.

검토: 초안 “인원 갈등 해결로 자원 통제 완료” → 환경 점검이 빠졌습니다 → 물적자원의 수량·상태·책임을 별도 확인합니다.

## 보고가 전달되고 이해됐는지 확인하기 (10.3)

사용 문서: D23 의사소통계획·배포기록. 근거: S10, S20.

확인할 수행: D23에 미확인 후속과 보고 형식 개선을 기록하세요. 현재 자료에 없는 이후 회신은 기다렸다가 변경 후 점검 단계에서 보완합니다.

검토: 초안 “참석률이 높으므로 모두 이해” → 이해 증거가 없습니다 → 확인 질문과 실행 여부를 추가로 확인합니다.

## 남은 위험을 재평가하고 계속 볼 항목 정하기 (11.7)

사용 문서: D25 리스크등록부·보고서. 근거: S07, S10.

확인할 수행: K02 잔여 기대손실을 계산하고 전체 노출을 비교하세요. 신규 기능의 권한 위험에는 아직 제공되지 않은 확률을 지어내지 말고 확인할 시험과 담당을 정합니다.

검토: 초안 “표본검증 통과이므로 확률 0” → 제공된 재평가와 다릅니다 → 실제 재평가 수치를 사용하고 대응의 한계를 설명합니다.

## 참여 상태를 날짜가 있는 증거로 평가하기 (13.4)

사용 문서: D31 참여계획·평가. 근거: S08, S10.

확인할 수행: 운영의 참여 상태와 근거를 찾아 목표와 비교하세요. 참석률 외에 요구 합의·시연·결정 참여 중 어떤 증거가 있는지 확인합니다.

검토: 초안 “설명을 보냈으니 지원 상태” → 상대의 반응을 확인하지 않았습니다 → 관찰 증거와 다음 확인 행동을 나눕니다.

## 분야별 사실을 한 장의 성과보고로 연결하기 (4.5)

사용 문서: D05 주간성과보고. 근거: S09, S10.

확인할 수행: 앞 단계의 원가·일정·품질·위험·자원·참여 정보를 기준일 하나로 모으세요. 스폰서에게 요청할 결정을 한 문장으로 작성하고 D06과 연결합니다.

검토: 초안 “문제없이 진행 중” → 남은 오픈 조건을 숨깁니다 → 현재 상태와 판단을 막는 조건, 담당·기한을 구체적으로 보고합니다.

## 변경 대안을 비교해 승인받을 안을 상정하기 (4.6)

사용 문서: D06 변경요청·결정대장. 근거: S02, S11.

확인할 수행: 세 대안의 영향을 D06에 나란히 적고 권고 이유와 다른 대안의 한계를 설명하세요. 지금 S2에서는 결정란을 승인 대기로 두고, 뒤의 S3 단계에서 실제 승인 조건을 대조합니다.

검토: 초안 “요청받았으므로 즉시 구현” → 기준선이 승인 없이 바뀝니다 → 영향 검토와 권고를 먼저 남긴 뒤 결정에 따라 관련 문서를 갱신합니다.
