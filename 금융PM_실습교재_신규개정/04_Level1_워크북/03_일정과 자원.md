# 03. 일정과 자원 - 문서 실습 안내

교재의 단계별 설명을 읽은 뒤 실제 산출물을 작성합니다. 웹에 다시 입력하거나 이 워크북에 본문을 중복 복사할 필요는 없습니다.

## 일정표의 달력과 갱신 규칙 정하기 (6.1)

사용 문서: D13 일정관리계획. 근거: S02, S06, S08.

확인할 수행: S08에서 점검 주기를, S02에서 기준선 변경 경로를 찾아 D13에 연결하세요. 일정이 달라졌다고 과거 기준선을 지우면 안 되는 이유를 설명합니다.

검토: 초안 “개발 완료일=프로젝트 종료일” → 이관·계약·재무 정리가 빠집니다 → 기술 완료와 종료 행정 완료를 다른 마일스톤으로 둡니다.

## 작업패키지를 활동과 완료조건으로 펼치기 (6.2)

사용 문서: D14 활동·일정표. 근거: S06, S18.

확인할 수행: E 통합검증의 담당·선행 활동·완료 증거를 S06/S18에서 찾아 작성하세요. “시험 완료”라는 말 대신 어떤 증거를 인도하는지 적습니다.

검토: 초안 “활동 C, 완료조건 개발 완료” → 확인할 결과가 없습니다 → 조회·권한·로그 인도물과 검토 증거를 D14 활동 정의 표에 연결합니다.

## 역할별 책임과 자원 요청 방법 정하기 (9.1)

사용 문서: D21 자원계획·RACI. 근거: S02, S06, S19.

확인할 수행: 운영 인수의 R/A/C/I를 작성하고 인력 요청·교육·배정 해제 방법을 D21의 운영 규칙에 적으세요.

검토: 초안 “개발 책임자가 일정 기준선도 단독 승인” → 작업 책임과 승인 권한을 혼동했습니다 → 기준선 변경은 PM 상정·검토 후 스폰서 결정으로 연결합니다.

## 필요한 사람과 환경을 수량으로 확인하기 (9.2)

사용 문서: D21 자원계획·RACI. 근거: S06.

확인할 수행: F의 운영지원 인원과 최종 인수시험을 수행할 운영자 수를 각각 찾아 쓰세요. QA 환경의 준비 예정일·관리자를 확인하되 실제 준비 완료는 실행 시점에 대조합니다.

검토: 초안 “운영 인수 대상은 5명” → 지원 인원과 실제 사용자 집단을 혼동했습니다 → 전환 지원 인원과 독립 수행을 확인할 운영자 3명을 구분합니다.

## 선후 관계를 그리고 병렬 작업 찾기 (6.3)

사용 문서: D14 활동·일정표. 근거: S06.

확인할 수행: D14의 선행 열을 읽으며 네트워크를 직접 그리세요. 시작부터 끝까지 두 경로를 따라가며 고립된 활동과 순환 화살표가 없는지 확인합니다.

검토: 초안 “C가 끝나면 E 시작” → D의 납품 조건이 빠집니다 → E의 선행을 C,D로 고치고 더 늦게 끝나는 경로를 기다립니다.

## 공수와 인원으로 기간의 타당성 검토하기 (6.4)

사용 문서: D15 추정근거. 근거: S06.

확인할 수행: E의 공수와 인원으로 같은 검산을 하고, D의 고정가 외주는 내부 인일 계산과 분리하세요. D15에 단위·조건·검토 근거를 남깁니다.

검토: 초안 “인원만 늘리면 기간이 정확히 절반” → 일을 나눌 수 있는 조건이 빠졌습니다 → 단순 환산값과 전문가가 제시한 실제 기간을 나란히 기록합니다.

## 네트워크를 계산해 실제 날짜로 옮기기 (6.5)

사용 문서: D14 활동·일정표. 근거: S06, S19.

확인할 수행: D와 E를 같은 방식으로 계산한 뒤 2026-10-19를 1일차로 날짜를 옮기세요. 두 경로 길이를 비교하고 계약 납기·인력 가용성과 대조합니다. 5·6단원 후 다시 확인할 항목을 남깁니다.

검토: 초안 “ES=20이므로 20일차 시작” → 하루가 당겨집니다 → 시작 일차는 ES+1, 종료 일차는 EF로 바꾸고 월~금 교육 달력에 배치합니다.
