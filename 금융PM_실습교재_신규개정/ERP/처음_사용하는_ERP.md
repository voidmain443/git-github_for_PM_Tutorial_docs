# 모의 ERP를 처음 사용하는 학생에게

## 1. 지금 열어 둘 화면은 두 개입니다

학습 안내 /learn에서는 설명·조회 경로·예제를 읽습니다. ERP 기본 화면 /에서는 회사 자료를 조회합니다. 「원천 ERP 열기」로 새 탭을 열고, 조회 후 안내 탭으로 돌아오세요. 웹페이지에 답을 입력할 필요는 없습니다.

문서를 직접 작성할 때는 해당 단계의 양식을 내려받아 자신의 작업 폴더에서 편집합니다. 원천 ERP는 바뀌지 않습니다. 문서 본문은 한 번 작성하고 워크북에는 사용한 문서·항목 위치만 남겨도 됩니다.

## 2. 왼쪽 메뉴를 선택하기 전에 질문을 정합니다

| 알고 싶은 것 | 선택할 메뉴 | 이번에 읽을 항목 |
|---|---|---|
| 누가 이 사실을 확인해 줄 수 있는가 | 조직·담당자 | 이름·역할·권한·관심 |
| 사업을 왜 시작하고 어떤 규칙을 지키는가 | 원천 문서 | S01 사업제안, S02 규정 |
| 가맹점에 줄 금액이 어떻게 계산되는가 | 가맹점 정산 | 정산번호·거래·취소·수수료·조정·지급예정 |
| 두 자료의 어느 거래가 다른가 | 거래 대사 | 계산액·수신액·차이·판정·담당 |
| 회사가 어떤 금액을 회계에 기록했는가 | 회계 전표 | 전표번호·계정·부호 있는 금액·근거 |
| 프로젝트 계획과 집행은 어떠한가 | 예산·기준선, 프로젝트 원가 | 계획 단계 이후 사용하는 메뉴 |
| 외주 인도와 지급은 어디까지 진행됐는가 | 구매·검수·지급 | 실행 단계 이후 사용하는 메뉴 |

0단원에서는 앞의 다섯 메뉴만 익히면 됩니다. 데이터 사전과 SQL부터 공부할 필요는 없습니다. 이후 단원에서 새로운 메뉴가 필요할 때 그때 익힙니다.

## 3. 검색칸과 정확히 일치 조건을 구분합니다

상단 큰 검색칸은 여러 열에서 입력한 글자를 포함하는 행을 찾습니다. 이름이나 문서ID를 처음 찾을 때 유용합니다. 검색칸에 “일치”를 넣으면 “불일치”도 그 글자를 포함하므로 함께 나올 수 있습니다.

아래 「정확히 일치」에서는 조건 항목을 먼저 고르고 옆 칸에 값을 씁니다. 판정=불일치처럼 한 분류만 보거나 정산번호=ST001처럼 특정 기록을 찾을 때 사용합니다. 두 조건과 검색어를 함께 넣으면 모두 만족하는 결과만 나옵니다. 이전 조건을 잊으면0건이 나올 수 있으므로 새로운 연습은 「초기화」에서 시작하세요.

예: 거래 대사 → 초기화 → 첫 조건 항목에서 판정 선택 → 첫 조건값에 불일치 입력 → 조회. S0에서는 결과12건입니다. 두 번째 조건을 거래번호=TX001001로 추가하면 특정 거래 한 건으로 좁힐 수 있습니다.

## 4. 목록과 상세를 구분합니다

목록은 비교와 검색을 위한 요약입니다. 첫 열의 밑줄 있는 식별자를 누르면 상세 창이 열립니다. 정산번호 ST001 상세에는 구성 거래와 예외, 거래번호 TX001001 상세에는 원천 거래와 예외처리 사유가 있습니다. P03 상세에서는 그 사람의 역할과 작성 문서를 확인할 수 있습니다. 상세를 닫아도 검색조건은 유지됩니다.

처음에는 모든 영문 필드를 해석하지 않아도 됩니다. person_id=인물ID, doc_id=문서ID, body=본문, owner_id=담당자ID, reason=사유, expected_net=계산액, received_net=수신액입니다. 코드가 다른 문서에 반복되면 같은 대상을 가리키는지 확인하는 연결 키로 사용하세요.

결과는50건씩 표시됩니다. 「검색 결과480건」인데 목록에50줄만 보이면 다음50건으로 이동할 수 있습니다. 현재 보이는 줄 수를 전체 건수라고 쓰지 마세요. CSV 내보내기는 현재 검색조건에 맞는 결과 전체를 저장합니다. 큰 자료는 최대10,000건 제한이 있지만 이 수업의 표본은 그보다 작습니다.

## 5. 조회 기록에 남길 여섯 가지

단계·기준일 / 메뉴 / 검색조건 / 행ID / 확인한 사실 / PM의 해석을 적습니다. 예를 들어 “금액 확인함”은 다시 찾을 수 없는 기록입니다. “S0, 가맹점 정산, 정산번호=ST001, 지급예정액222,440원, S05 조정 근거 대조”라면 다른 사람도 같은 사실을 재현할 수 있습니다.

PM의 해석은 사실과 구분합니다. “다음에 박다은에게 운영 인수 조건을 확인하겠다”는 자신의 후속 행동입니다. 아직 실제 회신이나 승인 기록이 없다면 확인 완료라고 적지 않습니다.

## 6. 금액과 날짜를 읽는 기본 규칙

ERP 금액은 원 단위입니다.241000은241,000원이며241백만원이 아닙니다. 교재의 백만원 단위 표는1백만원=1,000,000원으로 환산합니다. 정산번호의 날짜는 그 표본의 정산일, 전표의 전기일은 회계에 반영한 날, 실습 화면의 자료 기준일은 지금 공개된 정보의 시점입니다. 서로 같은 날짜라고 가정하지 마세요.

전표 금액의 양수·음수는 차변·대변 표시입니다. 현금 계정에서는 부호대로 더해 잔액을 확인할 수 있습니다. 수익 계정의 대변을 음수로 기록한다고 회사가 손실을 냈다는 뜻은 아닙니다. 처음에는 S04 재무 설명과 함께 읽습니다.

## 7. 비어 있는 화면도 읽을 수 있어야 합니다

S0는 착수 전입니다. 프로젝트 예산·기준선, 비용 실적, 발주, 검수 결과가 아직 없는 것은 정상입니다. 원천 S01에 사업 자금한도가 있어도 상세 승인 기준선 행은 별도로 생깁니다. 빈 결과를 “예산0원 확정” 또는 “시스템 고장”으로 기록하지 않습니다.

자료 단계가 S1·S2 등으로 바뀌면 새 사실이 추가됩니다. 이 사용 안내의 수치 연습은 S0 기준입니다.0단원 실습은 시작팩 S0에서 진행하고, 다음 자료팩은 교재의 인계 시점에 엽니다.

## 8. SQL은 선택 경로입니다

화면으로 조회한 뒤 동일한 결과를 확인하고 싶을 때만 SQL 조회 메뉴를 사용하세요. 아래 문장을 복사해 「SQL 실행」을 누를 수 있습니다. 읽기 전용이며 회사 데이터를 바꾸는 기능은 없습니다. 화면과 SQL의 자료 단계·필터가 같아야 결과를 비교할 수 있습니다.

```sql
SELECT * FROM v_정산조회 WHERE 정산번호 = 'ST001';
SELECT * FROM v_대사조회 WHERE 판정 = '불일치';
SELECT SUM(차변양수_대변음수) AS 현금잔액 FROM v_전표조회 WHERE 계정번호 = '100000';
```

한 번에 문장 하나씩 실행합니다. 첫 문장은 정산 배치 한 건, 둘째는 불일치 거래 목록, 셋째는 현금 계정 잔액입니다. SQL을 작성하지 못해도0단원과 헌장 실습을 수행할 수 있습니다.

## 9. 막혔을 때 확인할 순서

화면이 열리지 않으면 실습 서버가 실행 중인지 확인합니다. 파일 폴더만 열어 둔 상태로는 웹 화면이 열리지 않습니다. 실행 방법은 배포팩 README에 있습니다. 이미 다른 ERP 화면이 열리면 같은 주소의 /learn으로 돌아올 수 있습니다.

검색 결과가0건이면 자료 단계→선택 메뉴→초기화→조건 항목→값 순으로 확인합니다. 사람은 P, 원천 문서는 S, 정산 배치는 ST, 거래는 TX 코드입니다. 문서 버튼에 “이후 공개”가 붙으면 현재 단계에 없는 자료입니다. 검색 오류로 생각해 미래 자료팩을 먼저 열지 않습니다.

읽던 위치는 이 브라우저에만 보존됩니다. 이전 버전에서 작성한 학습 기록은 삭제하지 않으며 「이전 작성 기록 내려받기」로 보관할 수 있습니다. 새 문서는 내려받은 양식에서 작성합니다. ERP의 CSV 내보내기는 조회 결과를 보관하는 별도 기능입니다.

## 10. 자료팩을 바꾸는 순서

안내 목차는 어느 단원이든 볼 수 있습니다. 회사의 미래 자료와 그 결과를 쓰는 예제는 해당 자료팩을 열어야 표시됩니다. 먼저 현재 단계의 문서·검토를 마칩니다. 강사는 다음 팩을 공개하고, 개인 학습자는 완료 기준을 대조한 뒤 팩을 엽니다. 추가팩은 기존 폴더에 풀고 학습 안내 상단의 자료 단계에서 선택한 뒤 「선택한 자료 열기」를 누릅니다. 서버를 다시 시작하지 않아도 조회 시점이 바뀝니다. 아직 설치되지 않은 팩은 선택할 수 없습니다. 같은 서버를 쓰는 모든 탭에 적용되므로 ERP 탭도 새로고침합니다. 자료 열기는 문서 승인이나 학습 평가를 대신하지 않습니다.
